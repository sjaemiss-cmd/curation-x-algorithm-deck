# 트위터 2023 vs X 2026 — 동일 게시글 비교

https://sjaemiss-cmd.github.io/curation-x-algorithm-deck/experience/

동일한 실제 과거 원문 10,000개를 두 화면에 나란히 배치합니다. 왼쪽은 2023년 Twitter 규칙, 오른쪽은 2026년 X 규칙입니다. 원문과 공통 입력을 고정한 **공개 계산 규칙 실험**이며 실제 운영 모델의 성능 비교가 아닙니다.

## 사용

각 화면의 ‘가중치 조절’에서 슬라이더 또는 JSON 코드를 변경합니다. 설정은 서로 독립적입니다. ‘왜 이 순위일까?’를 선택하면 그 글이 양쪽에서 몇 위인지 상단에 나타납니다. 이용자·검색·팔로우 필터는 상단에서 양쪽에 동일하게 적용합니다. 모바일은 비교 영역을 좌우로 밀어 두 화면을 확인합니다.

로컬 실행: Node 22에서 `npm start`, http://127.0.0.1:8877 . 런타임 npm 의존성은 없습니다. `체험앱.html`은 서버 없이 실행 가능한 단일 HTML입니다. 재생성: `python scripts/build_standalone.py`. 검증: `npm test`.

## 같은 것과 다른 것

양쪽 후보 ID·원문 10,000개, 작성자 그룹·팔로우, 이용자가 동일합니다. 좋아요·답글·재게시·신고의 **실험 확률**을 양쪽에 그대로 공유합니다. 이는 실제 두 모델이 같은 예측을 했다는 뜻이 아닙니다.

2023년 ‘대화를 열고 2분 이상 체류할 확률’과 2026년 ‘체류 시간’은 정의·단위가 달라 같은 입력으로 강제하지 않습니다. 서로 대응하지 않는 항목은 별도의 고정 실험값입니다. 부정적 피드백 통합 값은 개별 확률의 단순 합이 아닙니다. 점수 절댓값은 시대 간 품질 척도로 비교할 수 없습니다.

같은 작성자 그룹의 다양성 배율은 두 코드 모두 `(1-floor)*decay^k+floor` 형태입니다. 그룹은 실제 작성자가 아니라 실험용 묶음입니다. 동점은 ID 순으로 고정하며, 이 동점 규칙을 운영 규칙이라고 주장하지 않습니다.

## 데이터

Cardiff NLP [TweetEval](https://github.com/cardiffnlp/tweeteval) sentiment train, 커밋 `4fbd22cd78421f05b1ecdb4fc5725bc7a7bd8f66`. 완전히 같은 텍스트를 중복 제거하고 seed 411로 10,000개 선택. 원문·행 번호·SHA-256은 `data/posts.json`, `data/provenance.json`에 보관했습니다. Unicode 이스케이프는 화면에서만 문자로 표시합니다.

출처: [TweetEval 논문](https://aclanthology.org/2020.findings-emnlp.148/), [원 sentiment 과제](https://aclanthology.org/S17-2088/). 데이터는 원 과제·TweetEval·Twitter의 이용 조건에 따릅니다. 코드를 위한 AGPL 허가를 데이터에 적용한다는 뜻이 아닙니다.

원 작성자·날짜·반응 수·이미지·영상은 없습니다. 반응 예상값은 글 길이·일부 단어와 결정적 난수로 만든 실험 입력이며 학습 모델이 아닙니다. Heavy Ranker/Phoenix 추론, 후보 검색, 평판·인증 등 전체 보정, Thompson Sampling, 광고 혼합, 전체 운영 필터는 재현하지 않습니다. 읽음 제외는 단순 Set membership입니다.

## UI·REA·검증

REA 6.8.0으로 X 페이지를 관찰하려 했으나 HTTP 403으로 막혔습니다. 로컬 초기 앱의 DOM·접근성 관찰은 성공했습니다. UI는 Twitter/X 형태의 교육용 모형이며 당시 앱 또는 현재 앱의 픽셀 단위 동일성을 검증한 것은 아닙니다.

계산·무결성 테스트 **17개 통과**. 세 이용자 조건 전체에서 10,000개 원문·ID·관계와 공통 확률 네 항목의 동일성을 검사했습니다. 2023 손계산·2026 원 소스 손계산 예제, 독립 조절, 음수·0·조건부 항목·다양성·필터를 확인했습니다. Scala/Rust 바이너리를 직접 컴파일한 대조는 아닙니다.

브라우저에서 두 화면 후보 일치, 다른 순위, 독립 가중치, 동일 글 양쪽 순위, 10/30개 기여분, 동시 이용자·검색 변경, 전체 초기화, 모바일 가로 비교, 단일 HTML 실행을 확인했습니다.

## 소스와 라이선스

수정된 구현은 이 디렉터리에 공개합니다. 2023 Twitter AGPL-3.0 코드에서 이식한 `twitter-engine.mjs`와 이 비교 앱의 작성 코드는 AGPL-3.0 조건으로 제공하며 `COPYING`을 포함합니다. 변경 내용: Scala 계산식을 JavaScript로 이식, 실험 입력·비교 UI 추가 (2026-11-10). 원본 Twitter 저작권·라이선스는 유지합니다. X 원 코드의 Apache-2.0 고지는 `evidence/LICENSE-X`에 유지합니다. 제3자 데이터·상표에는 각 원 권리가 적용됩니다.

공개 주소의 HTML/CSS/JavaScript, 데이터 JSON, 재생성 스크립트, 테스트 파일이 대응 소스입니다. 강의자료·비공개 Class 저장소·사용자 브라우저 캡처는 공개하지 않습니다.

## 한국어 번역 추가

원문 10,000개를 경량 모델 작업자 3개로 병렬 번역했습니다. 4,554개는 gpt-6.1-terra medium, 나머지 5,446개는 gpt-6-luna low를 사용했습니다. 번역 파일은 `data/posts.ko.json`, 생성·검사 정보는 `data/translation-provenance.json`입니다. `posts.json`의 원문은 변경하지 않았습니다.

한국어를 기본으로 표시하며 게시글마다 영어 원문을 펼칠 수 있습니다. 한국어·영어 검색 모두 가능합니다. 점수 계산은 계속 원래 영어 본문을 사용하므로 번역문 길이·단어가 추천 신호를 바꾸지 않습니다. 번역 전후 양쪽의 예측값과 전체 순위가 같아야 한다는 검사를 수행합니다.

AI 번역에는 고유명사·반어·줄임말·오타의 오역이 남을 수 있습니다. 자동 검사는 ID 완전성·빈값·중복·인코딩·멘션 등을 확인하며, 모든 문장을 사람이 의미 검수했다는 뜻은 아닙니다.


## 3D 기기 비교 화면

기본 `index.html`은 Three.js r180의 WebGL 기기 모델과 CSS3DRenderer의 실제 HTML 피드를 함께 사용합니다. 기기 뒷면에서 앞면으로 4.2초 등장하고 정착한 뒤에는 매 프레임 렌더링을 중단합니다. 다시 보기·건너뛰기·앞뒤 전환·모바일 한 기기 전환·모션 줄이기·WebGL 미지원 대체 화면을 제공합니다. 피드 스크롤과 가중치 조절은 실제로 동작합니다. 외부 CDN 없이 모든 라이브러리를 이 폴더에서 제공합니다.

- 2023 기기: iPhone 15 Pro, 70.6 × 146.6 × 8.25 mm 비율, 내추럴 티타늄 외형. [Apple 사양](https://support.apple.com/en-us/111829).
- 2026 기기: iPhone 18 Pro, 71.9 × 150.0 × 8.75 mm 비율, 버건디 외형. [Apple 발표](https://www.apple.com/newsroom/2026/09/apple-debuts-iphone-18-pro-and-iphone-18-pro-max/), [Apple 사양](https://support.apple.com/en-asia/148590).
- UI 기준: 개명 이전 Twitter의 추천·팔로우 피드와 X 다크 피드. [X 타임라인 안내](https://help.x.com/en/using-x/x-timeline). 2023년 출시 기기에 상반기 Twitter UI를 조합한 시대 표현이며 출시 당시의 앱 화면을 주장하지 않습니다.
- 공식 CAD나 전체 앱의 픽셀 복제품이 아닌, 공개 외형을 참고한 절차적 모델과 교육용 UI 재구성입니다. 원 작성자·사진·실제 반응 수가 없어 해당 자료를 임의로 만들지 않았습니다.
- 기존 넓은 화면은 `classic.html`, 오프라인 3D 화면은 `체험앱.html`, 오프라인 넓은 화면은 `비교앱.html`입니다.
- 빌드: `npm ci` 후 `npm run build`. Three.js 소스는 `vendor/`에 고정되어 있으며 esbuild 0.25.11은 개발용입니다. 번들 변경 없이 HTML만 다시 만들 때는 `python scripts/build_standalone.py`를 사용합니다.
- `phone-stage.mjs`: 기기·조명·등장·화면 배치. `stage-template.html` / `stage.css`: 비교 무대. `device-ui.css`: 기기 내부 UI. 추천 엔진과 1만 개의 원문·번역 데이터는 이 변경으로 수정하지 않았습니다.
- 검증: 계산·번역 테스트 17개, 로컬 3D 브라우저 검사 13개, 기존 비교 화면 검사 12개 통과. 1440px/390px 화면과 등장 중간·정착·뒷면을 확인했습니다. Windows Chrome에서 검증했으며 실물 iPhone/Safari의 동작·성능은 미검증입니다.

## 발표 전 준비와 캐시
발표할 PC의 Chrome/Edge에서 공유 주소를 열고 상단의 **발표 준비 완료** 표시를 확인하세요. 같은 브라우저로 재접속하면 화면·코드·한국어 게시글 1만 개를 로컬 캐시에서 읽습니다. 준비 후 인터넷을 끊어도 피드와 가중치 실험은 작동하지만 외부 출처 링크에는 인터넷이 필요합니다. 브라우저 저장 공간을 지우거나 다른 기기·브라우저를 쓰면 다시 준비해야 합니다.

콘텐츠 해시로 캐시 버전을 구분하고, 새 버전은 기존 체험 탭이 모두 닫힌 뒤 적용합니다. 발표 중 자동 새로고침은 하지 않습니다. 새 버전 안내가 보이면 체험 탭을 모두 닫고 공유 주소를 다시 열어 주세요. Service Worker가 지원되지 않거나 저장에 실패하면 온라인 기능은 유지됩니다. 원문과 번역은 병렬로 불러오고 3D 렌더링의 최대 pixel ratio를 1.75에서 1.25로 낮췄습니다. 피드 글자는 HTML이므로 이 해상도 제한의 대상이 아닙니다. 캐시는 통신 대기를 줄이며 CPU 계산·기기 성능·4.2초 등장 연출 자체를 없애지는 않습니다. 연출은 ‘바로 체험하기’로 건너뛸 수 있습니다.

검증: 로컬 캐시/오프라인/업데이트 대기·적용 테스트, 기존 3D 조작 검증, 계산·번역 무결성 테스트. 설계 참고: https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers

## 글을 눌러 두 시대의 순위 비교
트위터 글 본문이나 카드의 빈 영역을 누르면 X의 동일 ID 글로 이동하고, `트위터 n위 → X m위` 말풍선과 상승·하락 폭을 표시합니다. 순위는 현재 양쪽 실험 설정에서 가져옵니다. 좋아요·원문 펼치기·출처 링크 등 개별 버튼은 원래 동작을 유지합니다. 키보드는 본문에 초점을 맞추고 Enter/Space로 이동하며 Escape로 말풍선을 닫습니다. 모바일에서는 X 기기로 자동 전환합니다.

아직 화면에 없는 낮은 순위의 글은 해당 글 주변 최대 20개를 렌더링한 뒤 실제 주변 글 사이를 스크롤합니다. 수천 개의 글을 전부 지나가는 애니메이션은 아니며, `n위부터 보기 · 1위로 돌아가기`로 위치를 알립니다. 연속 클릭은 이전 이동을 취소하고, 가중치·검색·초기화로 결과가 바뀌면 오래된 말풍선을 지웁니다. X 후보에서 제외된 글은 순위를 만들지 않고 제외 상태를 표시합니다. 모션 줄이기 설정에서는 즉시 이동합니다.

## 재질 개선
금속 프레임의 미세한 결, 무광 후면 표면, 렌즈 코팅 반사와 연마된 테두리를 분리했습니다. 256×256 절차적 텍스처 3개를 공유하고 스튜디오 반사 조명은 초기화 때 한 번 계산합니다. 외부 텍스처 다운로드·실시간 그림자·후처리 패스는 추가하지 않았습니다. 후면 색조 맵은 표현을 위한 근사이며 실물 스캔이 아닙니다. 얇은 부품에 음수 extrusion depth가 생기던 형상도 수정했습니다.

양방향 비교: X 글을 눌러도 트위터의 동일 글로 이동합니다. 말풍선은 클릭한 쪽을 출발점으로 표시하고, 모바일은 반대 기기로 전환합니다. 어느 쪽 설정을 변경해도 오래된 순위 말풍선은 지워집니다.
